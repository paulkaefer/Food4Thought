Test Case 1: Successful Food Scan with Accurate Nutrition Results

Given a user has opened the food app and grants camera access
 When the user takes a clear picture of a grilled chicken salad
 Then the app identifies the food items in the image
 And calculates the total macronutrients (calories, protein, carbohydrates, and fats)
 And displays the micronutrients (vitamins and minerals) for the identified food items
 And presents the nutrition information within 5 seconds of the scan

Test Case 2: Multiple Foods in a Single Image

Given a user has opened the food app and is on the scan screen
 When the user uploads a picture containing grilled salmon, rice, and broccoli
 Then the app recognizes each food item separately
 And aggregates the macronutrient totals for the entire meal
 And displays the micronutrient breakdown for each individual food item
 And provides a combined nutritional summary for the meal

Test Case 3: Unsupported or Unclear Image

Given a user is using the food scanning feature
 When the user uploads a blurry or poorly lit image that cannot be confidently analyzed
 Then the app informs the user that the image quality is insufficient
 And explains why the food could not be identified
 And prompts the user to retake or upload a clearer image
 And does not display inaccurate nutrition data

Test Case: Multi-food identification with per-item and combined totals
Given a user uploads a clear photo of a plate with grilled chicken, rice, and broccoli
When the app analyzes the image
Then it identifies each food item individually
And estimates calories, protein, carbs, and fat for each item
And displays a combined total for the meal

Test Case: Dietary restriction conflict flagging
Given a user has previously set a dietary restriction (e.g., gluten-free, vegetarian, nut allergy) in their profile
When the app identifies a food item that conflicts with that restriction
Then it flags the item as a potential conflict rather than silently estimating nutrition
And prompts the user to confirm the ingredients before logging it

Test Case: Allergen labeling
Given a user uploads a photo containing shellfish, peanuts, tree nuts, or other common allergens
When the app identifies these items
Then it explicitly labels them as allergens in the results
Regardless of whether the user has a stated restriction on file

Test Case: Portion consumed via before/after photos
Given a user uploads an initial photo of a full plate
And later uploads a second photo of the same plate with less food remaining
When the app compares the two images
Then it estimates the portion consumed based on the difference
And does not assume 100% consumption unless the plate is empty in the second photo

Test Case: Food removed but not eaten
Given a user removes food from the plate without eating it before taking a second photo
When the app detects the reduced quantity
Then it does not automatically log the removed food as consumed
And asks the user to confirm what happened to the food

Test Case: Barcode/label precedence over visual estimation
Given a user uploads a photo of packaged food with a visible barcode or label
When the app detects the barcode
Then it prioritizes the manufacturer's published nutrition facts over visual estimation
And falls back to visual estimation only if no label is found

Test Case: Non-food image handling
Given a user uploads a non-food photo
When the app cannot identify any food items
Then it tells the user no food was detected
And does not generate or display any nutrition estimate

Test Case: Ambiguous portion size
Given a user uploads a photo where portion size is ambiguous (e.g., no reference object for scale)
When the app cannot confidently estimate serving size
Then it presents a range rather than a single exact number
And indicates that the estimate is approximate
